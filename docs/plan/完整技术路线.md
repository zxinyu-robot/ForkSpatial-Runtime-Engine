## 1. 各层/模块职责与边界

### 1.1 BT 运行时（MotionSLAM_ws）—— 支柱
- 中枢职责：技能编排、运行时条件检查、重试/超时/恢复分支、安全停止；Thin Harness 把 Task Intent 映射到本地技能入口。
- 插件机制：各模块以库/节点形式注册到 BT 运行时，通过契约 ① 交换 `LocalizationHealth / PolicyDecision / DecisionOutcome / AssetRef`；不同机器人、不同任务只换插件组合，不换中枢。
- 边界：`/cmd_vel` 不接受外部下发；TTL/session/generation 校验失败即停车；急停/限速/断链行为由设备侧独立保证；ROS overlay 冻结，新插件长在 overlay 外。

### 1.2 空间状态契约 + Token 资产管理（fork-spatial-runtime，插件 ①②）
- 契约（PR #7 已落）：`AssetRef{robot,session,asset_id,revision,generation,frame_id,asset_type?,hash?}`、`DeltaRef+dispose()`、`Stamp`、`LocalizationHealth→ExecutionAuthority`、唯一 `ReasonCode`、`admit()`。
- Token 编码器：迁移大模型 Token 机制做**物理空间资产管理**——几何→带语义价值的 Token，Token 携带 `ResourceRef(=AssetRef)`，TokenStore 管 TTL/revision/generation/frame 生命周期与实时一致性（代数切换批量失效、增量基线校验）。
- 约束：`asset_id` 是身份，Token 是资源句柄与编码；码本/编码器版本升级不改身份（防 F 阶段返工）。

### 1.3 ESN 状态语言编码器 + 结构化经验库（fork-spatial-runtime，插件 ③，两个角色拆开）
- **ESN = 编码器**：把**实时执行行为**（动作、结果、环境变化）翻译成**状态语言**——时序的状态-动作表示；输出给上游世界模型/规划模型（按"时空状态→动作→预测状态"建模），也给端侧调度模型做短期上下文。评价：**下游模型用 ESN 表示后的预测误差/决策质量**是否优于原始状态或滑窗特征。
- **结构化经验库 = 检索**：显式保存场景（Token 集合 + 可信度）→ 采取的策略 → 结果（含 `RecoveryOutcome`）的关联，供相似场景检索候选策略、按历史效果调整。评价：错误经验复用率、重复失败下降。记录字段按 Memory Record（memory_id/type/scope/preconditions/source/confidence/verification_status/invalidation）。
- 不负责：直接出控制或安全状态。两者都不默认"记住一次成功 = 学会一个技能"，经验先候选、经旁路比对再晋升。

### 1.4 端侧战术决策 + 在线学习调度（插件 ④）
两个角色，一条输出通道：
- **Jev —— 战术级判断模型**：输入 BT/规划器/③ 给出的候选集合与当前空间状态（AssetRef+LocalizationHealth+ESN 短期上下文），输出**类型化结果**（二选一 / 评分 / 概率），2.5 Hz 低频、70–500 ms 时延、概率可校准（长期与实际成功率对齐）。典型裁决：爬升 vs 绕行、等电梯 vs 走楼梯、进轿厢 vs 等下一班、继续 vs 回家。不参与高频控制，通过代码编排与反射层协作。
- **EdgePolicy —— 策略管理与在线学习**：active/candidate 双策略、旁路比对、晋升/回滚；维护 Jev 的校准统计（预测概率 vs 实际结果）作为晋升依据；**断网时**在 Task Intent 允许集合内接管局部调度。
- 统一输出 `PolicyDecision`：带 task_id、策略版本、Jev 输出类型与校准概率、引用 `AssetRef`、有效期、适用条件、降级原因——建议而非命令。
- 边界：候选来自 BT/规划器而非模型自造；不绕过 BT 与安全监督；不修改硬安全边界。

### 1.5 故障恢复插件（legged-navigation-runtime，插件 ⑤）
- 异构机器人通用：输入统一 `LocalizationHealth`，输出 `RecoveryAction→ExecutionAuthority/ReasonCode`；平台差异（四足 stance / 轮式打滑 / 人形重心 / 无人机高度）走可选 `PlatformHints`，不进核心状态机。
- 四足先闭环（`/lio/relocation/*`、`/lio/backend/drift_estimate` → 插件 → BT 恢复分支），后接其他平台。

### 1.6 弱网传输调度器（新模块，插件 ⑥）
- 不造传输：DDS 的 QoS 策略（可靠性/历史/期限/生存期/分区…）、UDP、5G-A 都是可选通道。
- 职责是**决策**：对待发消息按信息熵、字节大小、任务优先级、时效排序，决定发什么、走哪条通道、何时发；网差退化为只发心跳 + 本地 fragment log 缓存，网好后按 `DeltaRef` 基线补传；上行资产与下行 Intent 不要求一一对应。
- 评价：丢包/乱序/断链下关键消息（健康/原因码/安全事件）到达率与时延，补传后状态一致性校验通过率。

### 1.7 源头状态提供者（插件 ⑦）
- 常规：Super-LIO。
- 电梯内：LiDAR 退化、GNSS 无、楼层变化——参考 Elevator-LIO 类工作获取源头状态（楼层/门开合/轿厢运动），作为 `FloorTransition` 期间的 `LocalizationHealth` 来源；进出电梯时 `generation` 递增，旧楼层 Token 作废。

### 1.8 上游决策端（世界模型 / 规划器 / Harness / 人）
- 输入：空间资产快照+增量、ESN 状态语言序列、Execution Feedback。
- 输出 JSON Task Intent：到哪（目标区域/必经点/走廊）、完成什么（技能序列）、可采取什么策略（允许行为集合、behavior_policy）、路线与动态障碍预测、**交互动作建议**（如电梯按键/等待/进出时机）、`world_reference{asset_id, revision, generation, frame_id}`。
- 边界：下发技能级意图不是 BT 树；弱网下 Intent 可丢可迟，端侧按最后一次有效 Intent + ④ 继续；重连后以 Feedback 对账。

---

### 1.9 Token 的两种机制（第三份分享的结论，必须分开）
- **模型 Token（语义单元）**：几何→语义压缩，只走异步上行链路（Token + 增量 → 边缘/云），永不进控制回路；LIO 连续状态 \(x_t=[p,v,q,b]\) + 协方差走 SHM 给局部规划/控制，不离散化。混合表示：连续量保留数值、离散量用 Token、稀疏结构用索引引用、元数据带时间/坐标系/版本/置信度；词表带 `vocab_version`，先当契约定、不先学。
- **系统令牌（执行令牌）**：`lease{owner_id, epoch, expiry, clock, max_skew}` + `world_reference{generation, localization_epoch}`（字段以《下行JSON建议》§一.3 九字段为准）。这是"绑定机器人的可追溯链"：每条命令可查谁签发、第几任、基于哪版状态、何时过期；robot 不符 / epoch 低 / 过期 / 状态代数不符 一律拒绝。字段进 PR #8，多节点接管机制后置（H 阶段）。
- 评价（必须有数字）：带宽（均值/峰值/丢包恢复时间）、状态（重建误差/新鲜度/过期拒绝率）、调度（P50/P95/P99 时延、卸载比例、完成率）、安全（重复命令/过期命令/断网/所有权切换行为）。

## 2. 典型用例：跨楼层含电梯

```
楼层A导航(Super-LIO, Normal3D) → 到电梯口(Token: ElevatorDoor, 语义=可交互)
  → 上行实时状态经 ⑥ 下行 → 上游 Harness+模型给交互建议(按键/等待) 或 link 断 → ④ Jev 在候选{等电梯,走楼梯,回家}上出校准概率兜底
  → BT 执行交互技能(安全监督可否决) → 进轿厢: ⑦ 切 Elevator-LIO 源, LocalizationHealth.mode=Hold/FloorTransition
  → generation++ (楼层A Token 全部作废, dispose() 拒绝旧增量) → 出轿厢: 重定位 ⑤ Searching→Verifying→Tracking
  → 楼层B地图 AssetRef 生效 → 继续; 全过程 Feedback(ReasonCode+策略版本+状态版本) 回流, ESN 把这段行为编成状态语言给上游
```

## 4b. 研究主张与实验设计（总假设 + 三子假设）

| 层级 | 主张 | 对应能力 | 对照参考 |
|---|---|---|---|
| 目标 1 中间件 | 任务契约化 · 执行准入与生命周期治理 · 弱网状态与事件治理 | 能执行 | ROS 2 QoS 只管通信不定义任务语义 |
| 目标 2 恢复 | 在目标 1 的边界上，可信度驱动故障诊断、恢复动作选择、恢复后验证 | 能按可信度恢复 | HRI 2026 置信度感知恢复（模块级不确定性 + 人介入） |
| 目标 3 经验 | 在 1、2 的反馈上，Token 状态抽象 + ESN 状态语言 + 结构化经验库改善后续策略 | 能从经历改进 | MemER（经验检索）、ReSYNC（从失败学恢复技能） |
| 总假设 | 三者协同在不削弱确定性执行与安全约束的前提下提高复杂环境自主任务完成能力 | 协同 | 只能经交互效应间接检验 |

**三条关系接口 = 研究对象**（契约现状）：
1. Token → 恢复：`SpatialStateHeader{AssetRef, Stamp, LocalizationHealth}` 已有；**缺** `SemanticToken.source / verification_status / evidence_ref`。
2. 恢复 → 经验：`LocalizationHealth → ExecutionAuthority` 与 LNR `Verifying` 已有；**缺** `RecoveryOutcome{耗时, 代价, 恢复后状态是否满足继续条件}`。
3. 经验 → 运行时：候选只经 `PolicyDecision` 走准入，不绕 BT 与安全——已有。
→ 两个缺口已列入 §6 的 PR #8 范围（第 8、9 项）。

**E 阶段对照按子假设切，同一批 Go2 场景跑五组**：

## 7. 用词表（每个词一句话）

| 词 | 意思 |
|---|---|
| 旁路比对 | 候选策略只算不执行，把它"本来会怎么选"和实际执行结果放一起比，比得过才替换现用策略 |
| 旁路运行 / 旁路接入 | 新模块先只记录自己的判断、不控制机器人，用来验证它接的数据和给的建议对不对 |
| 代数（generation） | 空间上下文的"第几代"：定位重置、换楼层、换地图就加一；代数变了，旧状态一律不能再用 |
| 版本（revision） | 同一份地图/资产的内容更新次数；版本变了不等于作废，只是内容更新了 |
| 增量基线（base_revision） | 一个增量包是基于哪个版本算出来的；本地版本不等于它，就不能直接应用 |
| 原因码（ReasonCode） | 失败/降级的统一编号，三个仓库只用这一套，不再各写各的字符串 |
| 证据链 | 每次决策都能查到：用的哪版策略、基于哪版状态、实际结果是什么 |
| 可信度（LocalizationHealth） | 定位现在有多可信、为什么、还允许机器人做什么（正常/限速/暂停/收权） |
| Token（这里的） | 一块带语义标签的空间资源的"句柄"，带有效期和版本；不是资产的身份 |
| 执行令牌（ExecutionLease） | 一条命令的"授权凭证"：谁签发、第几任（epoch）、基于哪版状态、何时过期；旧任/过期的命令直接拒绝 |
| epoch | 执行者的"第几任"编号；接管一次加一，用来防止掉线的旧执行者还在发命令 |
| localization_epoch | 定位的"第几个有效周期"；定位重置就加一，只作废靠位姿锚定的状态，不作废地图资产（与 generation 分开） |
| 准入控制（Thin Harness） | 任务进 BT 前的六步检查：身份 → 租约 → 幂等 → 时效与空间 → 能力/安全/资源 → 生成已验证任务对象；任一步失败不进 BT |
| 关键事件 / 最新值 / 大块 | 上行数据三类：关键事件必须保留不可被覆盖；最新值旧的可丢；大块可分块续传 |
| 状态语言 | ESN 把机器人一段时间的动作和结果压成的时序表示，给上游模型用 |
| fragment log | 本地只追加不修改的日志，断网时它就是事实来源，网好了按它补传 |
| Thin Harness | 设备侧薄薄一层：解析任务、校验权限和版本、把任务映射到本地技能，不做规划 |
| Task Intent | 上游下发的任务意图：到哪、做什么、允许用什么策略；不是一棵行为树 |
