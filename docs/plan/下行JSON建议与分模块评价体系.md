## 一、下行 JSON：从 DJI 物模型迁移到具身实时（按第四份分享的批评修订）

> 核心不是 JSON 转二进制，而是把 IoT 的"服务调用"升级成**带执行权、时效、空间版本、能力边界、失联策略的任务执行契约（Intent Execution Contract）**。

### 1. DJI 物模型三要素 → 具身契约（不一一等同）

| DJI 物模型 | 具身映射 | 说明 |
|---|---|---|
| 属性 | **Asset**（地图/子图/楼层/坐标系/空间对象）· **Health**（定位健康/规划器/传感器/执行器诊断）· **State**（位姿/速度/任务阶段） | 三者更新频率、存储、有效期、丢失处理都不同，不塞一个属性集。契约类型已分：`AssetRef / LocalizationHealth / RobotState` |
| 服务 | **Task Intent**（长时自主任务）· **Query**（读电池等即时查询）· **Configure**（配置） | 查询/配置不建 BT 任务 |
| 事件 | **Execution Feedback**（任务）· **环境事件** · **安全事件** | 不把所有事件当任务结果 |

更正：DJI 物模型本身支持定频 / 变化触发 / 主动查询等上报方式，"事件上报、弱网适配"不是它缺的；我们的增量在于**自主任务执行语义**。兼容它的上层接口，内部建自己的任务语义层。

### 2. 规则一：JSON 放边界，内部实时链路用契约生成的 DDS IDL
- 是否进实时链路由**时延预算、抖动/尾延迟、数据大小与分配行为、是否允许过期丢弃、丢包重传对决策的影响**决定；"≥10 Hz / ≤100 ms"只作默认启发，不是硬线（5 Hz 但超时会让机器人沿错误轨迹继续的数据也要严格时效契约）。
- 二进制 ≠ 实时：DDS Deadline / Liveliness / Lifespan QoS 只能监测间隔、存活、有效期，替代不了应用层契约；线程调度、队列积压、动态分配、锁、QoS 配错都会超时 → 必须压测时延、抖动、分配、过期处理。
- 一套类型系统：从 `spatial_state.h` 等契约生成 IDL，不另引 Protobuf/FlatBuffers。

### 3. 规则二：Intent Execution Contract 的九个字段

```json
{
  "intent_id": "edge_a:task_001:3",
  "idempotency_key": "edge_a:task_001",
  "schema_version": "intent.v1",
  "lease": { "owner_id": "edge_a", "epoch": 7, "expiry_ns": 0, "clock": "wall_utc", "max_skew_ms": 50 },
  "world_reference": { "map_id": "b1/f2/map", "floor_id": "f2", "generation": 3,
                       "localization_epoch": 11, "frame_id": "map" },
  "start_deadline_ns": 0, "execution_timeout_ns": 0,
  "allowed_actions": [ { "action": "navigate", "max_speed_mps": 0.8, "area": "zone_B" },
                       { "action": "elevator_wait" }, { "action": "recover" }, { "action": "return_home" } ],
  "policy": { "on_link_lost": "continue_local", "on_lease_expired": "hold",
              "on_deadline_missed": "cancel", "on_invalid_world_state": "pause_and_resync" },
  "skill_sequence": [ ... ], "navigation": { ... }
}
```

| 字段 | 约束什么 | 规则 |
|---|---|---|
| `intent_id` / `idempotency_key` | 追踪 vs 去重，不是一回事 | 同键同内容 → 返回原任务/原结果，不重跑；同键不同内容 → 拒绝并记冲突；键有作用域和保留期；原请求已过期也不能因重校验失败而误启第二个任务 |
| `lease{owner, epoch, expiry, clock, max_skew}` | 执行权与陈旧控制权 | **epoch 是单调递增的栅栏**，低于本地已接受值一律拒绝；只比 expiry 不够（时钟偏差/延迟/重放） |
| `world_reference{map_id, floor_id, generation, localization_epoch, frame_id}` | 任务引用的世界是否还成立 | `generation` = 空间资源代数（换图/换楼层），变 → 全作废；`localization_epoch` = 定位有效周期（定位重置），变 → 只作废位姿锚定的状态。不匹配时三分：**可确定性重定位 → 允许重验证/重规划；语义失效 → 拒绝；无法确认 → 暂停进恢复** |
| `start_deadline_ns` / `execution_timeout_ns` | 最迟开始 vs 最长运行 | 必须声明时钟域与允许偏差；租约过期 / 启动截止 / 运行超时是三种失效，原因码分开 |
| `allowed_actions`（类型化能力集合 + 参数约束） | 上层意图越权 | 是授权边界不是命令；**不能覆盖底层安全限制**（碰撞/稳定性/运动限制/急停更高优先级） |
| `policy{on_link_lost, on_lease_expired, on_deadline_missed, on_invalid_world_state}` | 三种失效的本地行为 | 策略声明，由本地安全状态机解释，不是远端指定底层运动命令；走廊里已验证的导航短暂断网可继续，依赖远端实时批准的危险动作必须停 |

### 4. 规则三：Thin Harness = 准入控制（Admission Control），不是 JSON 校验器

```
1 入口与身份      消息大小上限、发送方身份、目标机器人、协议版本
2 租约与执行权    owner / epoch / 租约状态；陈旧控制者不能提交
3 幂等性          重复请求返回已有任务状态，不重跑
4 时效与空间有效  start_deadline、generation / localization_epoch、frame、前置条件
5 能力/安全/资源  allowed_actions 与参数约束、底层安全限制、资源冲突
6 生成已验证任务上下文 → 进 BT       BT 收到的是验证过的任务对象，不是原始 JSON
```
- 任一步失败 → 拒绝 + 原因码 + 安全行为，不进 BT。
- 一次性准入不能替代执行期持续校验：世界状态和租约在运行中仍会变，BT 关键节点要重查前置条件——**但必须复用同一份 `admit() / dispose()`**，不能让 BT 节点各写一套，否则"原因码只有一套"被破坏。

### 5. 规则四：上行调度器按数据分类，不只是降频

| 类别 | 例子 | 调度 | 弱网行为 |
|---|---|---|---|
| **关键事件（Durable event）** | 急停、严重故障、任务终止、执行权变化、进入/退出恢复 | 高优先级、需确认与重试 | 不能被状态流量挤压；**不能被后来的"已恢复"最新值覆盖**（ESN 状态语言与证据链依赖这段历史） |
| **最新值（Latest-value）** | 位姿、速度、动态状态 | 最新优先、按价值调度 | 合并旧值、丢弃过期样本 |
| **任务反馈事件** | BT 阶段、规划失败、恢复过程 | 事件驱动，带原因码与 intent_id | 保留关键状态转移，不只剩最终结果 |
| **大块（Bulk）** | 地图、点云、图像、日志 | 低优先级、分块、可恢复 | 降频 / 暂停 / 断点续传 |
| **心跳与健康摘要** | — | 低频周期 + 异常触发 | 维持失联与健康判断 |

类间优先级由分类定，类内排序再用信息熵 / 字节 / 时效。调度器只管传输，**不是安全闭环的必要部分**：断网时机器人靠本地估计、规划、BT、控制继续允许的任务或进本地安全策略。

### 6. 反馈状态
`ACCEPTED / RUNNING / BLOCKED / RECOVERING / SUCCEEDED / FAILED / CANCELLED / PREEMPTED`，带 `intent_id`、原因码、实际使用的空间版本（generation + localization_epoch + revision）。区分"请求已接收"与"任务已完成"。FSR 现有 `MissionStatus` 缺 ACCEPTED / BLOCKED / PREEMPTED，待补。

### 7. 落点与第一阶段闭环
- 定位为独立的 **Embodied Intent Runtime**（Intent Adapter + Thin Harness + Task Runtime/BT Orchestrator），不重做导航框架 → 落 `MotionSLAM_ws/runtime/`（overlay 外）。
- 第一阶段只做一个闭环：外部提交导航 Intent → Harness 六步准入 → BT 执行；运行中租约失效 / 版本变化 / 定位失效按原因分别拒绝启动、暂停、重规划或恢复 → 统一 Execution Feedback 返回。
- 作为中间件（目标 1）的三条主张：**任务契约化 · 执行准入与生命周期治理 · 弱网下的状态与事件治理**。它们不替代目标 2（可信度驱动恢复）与目标 3（Token/ESN 经验积累），是其中间件切片。

## 二、分模块评价体系（代替"风险点"）

原则：每个模块一组指标 + 一个基线 + 一个参考评价体系。标注 **[已知]** 为我能确认出处的，**[待核实]** 为方向对但需查证具体论文/基准的。

### M1 定位与状态估计（Super-LIO / Elevator-LIO 类源）
| 指标 | 定义 | 参考 |
|---|---|---|
| ATE / RPE | 绝对轨迹误差 / 相对位姿误差 | **[已知]** TUM RGB-D 基准（Sturm et al. 2012）定义；EuRoC（Burri et al. 2016）、KITTI 里程计常用 |
| 退化场景鲁棒性 | 电梯轿厢、长走廊、玻璃区的漂移与失效率 | **[已知]** Hilti SLAM Challenge 系列侧重建筑/退化场景；具体电梯内评价 **[待核实]** Elevator-LIO 原文指标 |
| 协方差一致性 | NEES / 一致性检验 | **[已知]** 滤波类估计的标准检验 |

### M2 重定位与故障恢复（LNR 插件）
| 指标 | 定义 | 参考 |
|---|---|---|
| 失效检测召回/误报 | 真失效被检出的比例 / 正常被误判失效的比例 | 自定（回放日志标注） |
| 恢复时间 MTTR | 从失效确认到 Tracking 恢复的时间分布（P50/P95） | 自定 |
| 重定位成功率 @ 位移/旋转扰动 | 不同初值误差下的收敛率与 fitness | **[待核实]** 场所识别/重定位论文（如 Scan Context 系列）常用 recall@N，可借用 |
| 安全停车触发正确率 | 该停时停、不该停时不停 | 自定 |

### M3 导航与任务执行（BT 运行时 + PCT/SCAN）
| 指标 | 定义 | 参考 |
|---|---|---|
| SR（Success Rate） | 到达率 | **[已知]** Anderson et al. 2018《On Evaluation of Embodied Navigation Agents》 |
| SPL | 按路径长度加权的成功率 | **[已知]** 同上，具身导航标准指标 |
| 长时程任务完成率 / 子目标完成率 | 整任务 vs 子目标两个口径 | **[已知]** LongAct 基准报告两个口径（目标完成率 59% vs 整任务 16%，第一份分享） |
| 碰撞 / 安全违规次数 | 每任务 | **[已知]** Habitat 等具身基准常报 collision |
| 跨楼层特有 | 楼梯成功率、电梯进出成功率、楼层识别正确率、换图后首个子目标到达时间 | 自定（本项目特色，可作贡献点） |

### M4 空间状态契约与 Token 资产管理（FSR ①②）
| 指标 | 定义 | 参考 |
|---|---|---|
| 过期状态拒绝率 | 代数不符/过期的状态被 admit() 拒绝的比例（应 100%） | 自定，PR #7 测试即雏形 |
| 状态新鲜度 | 消费时状态年龄分布 | **[已知]** AoI（Age of Information）是通信领域标准度量 |
| 重建误差 | Token/增量重建 vs 原始地图的几何误差 | 自定；地图评价可借 **[待核实]** 占据栅格/体素地图精度评价方法 |
| 一致性校验通过率 | 补传后本地 revision/hash 与源一致的比例 | 自定 |

### M5 ESN 状态语言编码器 + 结构化经验库 + Jev/EdgePolicy（FSR ③④）
| 指标 | 定义 | 参考 |
|---|---|---|

|---|---|---|
