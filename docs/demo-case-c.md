# 案例 C：空间状态与智能系统交互

**案例整理与署名：zxinyu**

## 目标

把机器人的空间状态可靠地提供给上层智能体、任务运行时和世界模型，使状态来源、版本、置信度、有效期和失败语义能够被下游明确消费。

## 公开重构范围

本仓库是历史工程的可构建、可测试公开重构，当前聚焦：

- 状态契约与版本链；
- 执行租约和准入判定；
- 增量空间状态与因子图事务；
- 定位恢复状态；
- 地形契约；
- 弱网协同与共享内存融合；
- 只读诊断和可控故障演练。

核心实现与可运行示例位于 `src/` 和 `examples/cpp/`，构建与测试方式以仓库 README 为准。

## Demo 目标

案例演示的是“空间状态 → 任务意图 → 安全动作 → 新状态”的交互边界，而不是某个单一 SLAM 后端。运行时通过契约桥接到机器人执行栈，插件提供证据或建议，不直接取得执行权。

Go2 跨楼层导航通过契约桥接接入本仓库；相关端到端演示和硬件适配仍在 [quadruped-crossfloor-nav-ws](https://github.com/zxinyu-robot/quadruped-crossfloor-nav-ws) 维护。

## 当前限制

- 公开仓库不包含历史商业系统、厂商 SDK 或完整机器人部署环境；
- 与真实机器人、世界模型或多机系统的集成需要在对应项目中单独验证；
- 当前示例证明接口和状态语义可构建、可测试，不等同于完整自主系统性能结论。
